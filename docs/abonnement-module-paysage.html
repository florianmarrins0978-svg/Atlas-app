Ce que le code devra faire (niveau 3 : c'est de l'argent)

↑ Sommaire
  1. La règle (src/lib/abonnements.ts) : une liste fermée de modules, son prix, ses fonctions ; fonctionOuverte lit la formule ET les modules ; les trois outils quittent les fonctions d'Entreprise et d'Illimité ; la ligne des salariés devient réservée ; Artisan compte tous les accès, pas seulement ceux qui facturent.
  2. L'essai ouvre toujours tout, Paysage compris : on essaie tout, on choisit après (FORMULE_DE_LESSAI).
  3. La base : les modules souscrits, sur la ligne d'abonnement, en expand (colonne ajoutée, vide par défaut).
  4. Le paiement : une seconde ligne dans la page de paiement, et l'ajout ou le retrait du module au prorata sur un abonnement qui court ; les modules relus au retour et au crochet, comme la formule.
  5. Les deux refus : inviter un salarié sur Artisan, et passer à Artisan avec d'autres comptes.
  6. Les écrans fermés : « Le plan d'arrosage est dans Entreprise » devient « dans le module Paysage », pour les trois formules.
  7. La facture d'abonnement de Cause : une ligne de plus pour le module.

Ce qui a été trouvé en chemin

↑ Sommaire
  • Un écart déjà là, sans rapport avec le module : passer d'Entreprise à Artisan avec trois personnes qui facturent n'est refusé nulle part aujourd'hui (le plafond ne se vérifie qu'à l'invitation), alors que l'article 14.6 le promet. Le refus du point 5 le fermera.
  • Les conditions générales publiées (version 3) disent le contraire : « Les comptes salarié ne sont pas comptés et ne donnent lieu à aucun supplément, quel que soit leur nombre » ; Entreprise et Illimité y « comprennent les outils de paysage » ; le module n'existe pas. Il faudra une version 4, que chaque compte acceptera de nouveau. La publier est sa décision.
  • PRODUCT.md dit encore que l'arrosage, le diagnostic et les fiches « font partie du cœur, pas d'un module optionnel ». À corriger au codage.
  • Aucun abonné réel : personne ne perd Paysage en cours d'abonnement.
