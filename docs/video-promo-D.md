## 7. Le cahier du son

**Personne n'a écouté les bandes ici** : cet environnement n'a pas de
haut-parleur. Les bandes livrées sont synthétisées (`scripts/musique-film.py`),
dans une seule tonalité, pour qu'elles ne puissent pas être fausses ; elles
servent à sentir le rythme, pas à être gardées. Les versions muettes sont à
côté.

**Comment un film et son son se tiennent.** Chaque page déclare sa **carte
des temps forts** (`window.SONS` : l'instant de chaque coup, chaque appui,
chaque raccord) et sa **carte musicale** (`window.MUSIQUE` : tonalité,
sections, et le tempo de chaque section). Le rendu les écrit dans un fichier
(`rendre-film.mjs --sons`), et c'est ce fichier qu'on donne à qui pose le
vrai son : chaque impact a son instant au centième.

| | Le coup de poing | La journée |
|---|---|---|
| **tempo** | 128 à la noire de bout en bout, si mineur puis ré majeur | 92 à la noire, si mineur (la nuit) puis ré majeur |
| **la courbe** | pulsation sur chaque temps et coup sur chaque mot ; charley serré pendant l'accélération ; silence au noir ; la pulsation reprend avec « 30 », l'arpège entre sur la dictée, la nappe sur « Devis. » ; silence au second noir ; nappe seule sur « Le soir. » ; silence ; carillon sur « Atlas » | nappe froide et tic d'horloge le soir ; la nappe se réchauffe à 8 h 05 avec l'arpège ; la basse n'entre qu'aux raccords (8 h 06, 12 h 31, « Sans vous appeler », 18 h 20) ; le charley sur la facture ; nappe seule quand le téléphone se pose ; silence ; carillon sur « Atlas » |
| **les impacts à caler** | les six coups de 0 à 2,8 s (un tous les 0,47 s) ; le noir à 4,7 s ; « 30 » à 5,2 s ; « RÉDIGEZ. » 7,5 s ; « OU DICTEZ. » 8,4 s ; le micro 8,9 s ; le filé 12,2 s ; « DEVIS. » 12,7 s ; « PRÊT. » 13,1 s ; « LE CLIENT. » 14,1 s ; « PRÉVENU. » 15,9 s ; « PLANNING. » 17,3 s ; « LES GARS. » 18,8 s ; « SANS VOUS APPELER. » 22,0 s ; « FACTURE. » 23,4 s ; « LA TVA. » 25,8 s ; « À DÉCLARER. » 28,1 s ; le noir 29,5 s ; « 20 minutes » 30,0 s ; « 30 secondes. » 30,9 s ; « Le soir. » 31,9 s ; « Atlas » 33,3 s | la bascule 4,6 s ; le micro 12,5 s ; le raccord du devis 15,8 s ; les appuis du client 19,6 s et 20,1 s ; la notification 21,5 s ; l'envol 23,1 s, la pose 24,0 s ; la fiche 28,6 s ; la facture 33,8 s ; la TVA qui se détache 36,9 s, qui se pose 41,5 s ; le téléphone posé 45,4 s ; « Atlas » 47,1 s |

## 8. Les captures, et les deux écrans retenus

**La fiche de chantier du planning pour les gars**, c'est **la fiche
d'intervention** : sur le planning, toucher le chantier du jour ouvre une
carte cernée d'or, « Fiche d'intervention », avec le nom du client, Maps,
Waze, Copier l'adresse, Appeler le client, la fiche de sécurité, et le
bandeau « Travaux à faire » qui déplie les lignes du devis en cases à cocher.
C'est le seul écran qu'un salarié atteint (`docs/QUESTIONS.md` §10), et c'est
**la vue de Julien, salarié**, qui est dans les deux films : pas un prix.

**Le chemin « je rédige »**, c'est **l'éditeur de lignes** : le bouton
« Je rédige à la main », sous le micro de la fiche client, crée le chantier et
ouvre `/chantiers/<id>/devis-complet`, le devis sur papier avec ses lignes à
taper (« + Ajouter une ligne », qté, unité, prix). Il est capturé vide, puis
avec la première ligne tapée. Le devis de démonstration, lui, est parti chez
la cliente et ne se modifie plus : son écran n'est plus un éditeur, c'est
pourquoi l'éditeur a été capturé sur un devis neuf, pour la même cliente.

**Le jeu de démonstration est dans le dépôt** : `scripts/preparer-jeu-du-film.mts`
le reconstruit en jouant les gestes dans un vrai navigateur, et
`scripts/capturer-ecrans-du-film.mts` reprend toutes ces captures à l'échelle 3
(`planning`, `facture`, et désormais `editeur`). **Une correction au passage** :
le nom de la cliente du jeu portait sa civilité (« Mme Martin »), alors que la
civilité est un bouton à part sur la fiche ; l'éditeur écrivait
« Mme Mme Martin ». Le nom est désormais « Martin », civilité « Mme ».

**Un seul taux de TVA.** Le chantier de démonstration est à 20 %, donc la
table « par taux » n'a qu'une ligne. Rien n'a été inventé pour en montrer deux.

## 9. Ce qui a été fait autrement que le brief, et pourquoi

| Le brief, ou votre demande | Ce qui a été fait |
|---|---|
| « 30 à 40 secondes » | le coup de poing fait 37 s ; la journée fait 53 s, parce que chaque écran y est tenu entier, et que vous avez demandé de voir toute l'appli. Ce qui peut sauter si c'est trop long : la page du client (3 s), ou la fiche des gars (7 s) |
| « Three.js ou CSS 3D » | CSS 3D. Le rendu se fait dans un Chromium sans carte graphique ; un téléphone en WebGL y aurait coûté dix fois plus par image |
| « flou de mouvement », « grain » | rendus pour de vrai au rendu : deux sous-images par image, moyennées ; un grain à graine fixe (`rendre-film.mjs --obturateur 2 --grain 8`) |
| « 1920 × 1080 si le temps le permet » | pas fait : votre verdict sur les films verticaux d'abord |
| « le payoff : une image, pas une phrase » | tenu dans la journée (le téléphone posé, l'écran éteint, rien d'écrit). Dans le coup de poing, « Le soir. » revient en écho de l'ouverture, avec le téléphone posé : c'est l'image qui répond au mot |
| « demande-lui avec une capture » (la fiche des gars) | retenu la fiche d'intervention sans attendre (§8) |

**Ce que les planches ont montré de faux, corrigé avant les rendus** : dans la
journée, l'horloge rangée dans le coin se coupait au bord du cadre dès que la
caméra s'approchait (elle vit désormais dans le cadre, pas dans le monde, et
s'efface sur les plans rapprochés) ; la grande horloge recouvrait la phrase
précédente à chaque changement d'heure (les phrases partent avant) ; les
repères de lieu se perdaient dans les chiffres (ils attendent que l'horloge
soit rangée). Dans le coup de poing, les mots des piliers se coupaient au bord
quand la caméra sautait dans l'écran (ils vivent dans le cadre, sur un voile
sombre, sans quoi le blanc de l'écran passait sous le mot blanc) ; « 30 »
disparaissait derrière le téléphone entier ; « 20 minutes » sur deux lignes
ne se laissait pas rayer. Et dans les deux : une fiche client qui revient
après l'éditeur restait éteinte, parce que le moteur ne savait pas qu'un
écran peut revenir plus loin dans le découpage.

**Et ce qu'une seconde lecture, bande par bande, a encore trouvé dans la
journée** : le monde entier était posé 40 pixels trop haut, si bien que les
repères de lieu et la dictée venaient mordre sur l'horloge rangée dans le coin
(la caméra vise désormais le centre exact du cadre quand elle ne zoome pas) ;
« Rédigez à la main. » et « Ou dictez. » se chevauchaient une demi-seconde ;
la ligne du devis, en quittant la transcription, atterrissait sur le titre
« Transcription » de l'écran suivant (elle se pose plus haut) ; et la capture
de l'éditeur avait été prise après que la ligne saisie eut fait défiler la
page de 39 pixels, ce qui coupait le haut de l'écran (la page est remontée
avant la photo, et c'est écrit dans le script de capture). Puis, sur la
planche rendue après ces corrections : « Ou dictez. » sortait du cadre dès
que la caméra plongeait sur le micro, lisible un quart de seconde, alors que
la dictée est le point que vous avez dit essentiel. La suite du film est
décalée d'une seconde (51 s au lieu de 50) : la phrase s'écrit sur la fiche
entière, le micro cerné d'or sous elle, et la caméra ne descend qu'ensuite.

**Puis une relecture hostile, bande par bande, sur la planche de la journée
(vingt et une bandes lues, chaque constat rejoué en pleine taille)** : l'horloge
s'éclipsait pendant son passage à 8 h 06, parce que la minute roulait au
moment même où le zoom la range (elle roule maintenant avant) ; la ligne du
devis, en montant, couvrait l'encoche et le titre « Transcription » un quart
de seconde (le téléphone recule pendant qu'elle monte) ; la page du client,
qui n'a pas la marge des écrans de l'appli, passait sous l'encoche (descendue
de 60 points, la bande découverte de la couleur de la page) ; « Le devis est
prêt. » restait lisible 0,3 s et le repère « votre client » ne s'affichait
jamais, sa fenêtre étant inversée (deux secondes rendues à ce passage : la
journée fait 53 s). Les constats sur l'encoche qui cache le contenu qui défile
dessous n'ont pas été retenus : c'est ce que fait un vrai téléphone.

**Et dans le coup de poing, relu à la main sur les mêmes bandes** : le « 30 »
de « 30 secondes » était posé derrière le téléphone, qui en cachait le bas
(il tient maintenant au-dessus) ; les mots de l'ouverture frappaient à une
taille qui touchait les deux bords (« LES GARS. ») ; « SECONDES. » débordait
du cadre pendant son coup d'entrée ; « LE SOIR. » de la fin se levait derrière
le téléphone posé (il se pose maintenant après la phrase) ; et la table de TVA
arrivait pendant que la caméra était encore dans l'écran, donc une fois et
demie trop grande et coupée sur trois côtés (la caméra ressort d'abord).

**Un défaut vu dans le film, mais qui est dans l'application** : l'en-tête
de la facture écrit « F2026-000001 — Mme Martin », avec un tiret. Il vient
de `FactureClient.tsx`, pas du film, et le contrôle des tirets ne le voit pas
parce qu'il suit un composant. Il est noté dans `TODO.md` pour un lot à
part ; le film le montre tel quel tant que l'écran n'est pas corrigé et
recapturé.

## 10. Ce qui reste, et qui peut le trancher

| | Qui |
|---|---|
| le verdict sur les deux films, la longueur de la journée, le nom, l'adresse de fin, la voix | le patron |
| écouter les bandes de travail et dire si le rythme est le bon | le patron (rien n'est audible ici) |
| le vrai son, sous licence ou enregistré, sur les cartes des temps forts | un musicien ou une banque de musique, avec les `sons.json` |
| la déclinaison 1920 × 1080 | après son verdict sur le vertical ; une demi-heure de rendu par film |
| pousser sur `main` (et donc rendre la page lisible à son adresse publique) | sur son accord seulement |

**Pour refaire un film** (une demi-heure de rendu) :

```
node scripts/rendre-film.mjs appli/video-promo/film/film-D-recit.html --planche /tmp/p.png --pas 0.25
node scripts/rendre-film.mjs appli/video-promo/film/film-D-recit.html --ips 60 --obturateur 2 --grain 8 --sons sons.json --sortie appli/video-promo/atlas-D-recit-muet.mp4
python3 scripts/musique-film.py --sons sons.json --sortie bande.wav
ffmpeg -i appli/video-promo/atlas-D-recit-muet.mp4 -i bande.wav -c:v copy -c:a aac -shortest appli/video-promo/atlas-D-recit.mp4
```

La première commande est celle qu'on REGARDE avant de lancer le rendu ;
`--instants 15.8,23.5 --dossier /tmp` rend une image en pleine taille pour
vérifier un raccord. Les captures de l'éditeur se reprennent avec
`npx tsx scripts/capturer-ecrans-du-film.mts editeur`, le serveur et le jeu
de démonstration en place.
